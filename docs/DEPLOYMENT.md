## 当前未闭合的自动发布问题

创建 Vercel Git 项目时，平台提示该团队没有安装或授权 GitHub 集成。为了让演示网站能先被访问，首版采用 Vercel API 的**直接文件部署**，没有申请任何新的 OAuth 许可、个人 Token 或付费计划。

这意味着：

1. GitHub 的 `main` 是项目源码与标准的权威来源。
2. 当前 Vercel 已发布的是初始静态网页文件快照，**提交到 `main` 不会触发 Vercel 自动部署**。
3. 用户批准并安装最小权限的 Vercel GitHub 集成后，可把现有 Vercel 项目关联到本仓库，按 `main` 自动发布，PR 生成预览。不要建立第二个同名站点，也不要给 OAuth 客户端额外的 `repo` 权限。
4. 连通自动发布前，任何代码变化要显式发布、测试、记录部署版本，不得宣称 GitHub 与生产站点同步。

## 未来接入 GitHub 登录与私有结果的门槛

- 先确认用户愿意保存自己的政治／价值观结果，再接入 Supabase GitHub OAuth、隐私政策、会话验证、数据库 RLS 与删除机制。
- OAuth 秘钥仅配置在 Vercel / Supabase 的私密环境变量，绝不写入公开 GitHub。
- 必须用两个互不相关的测试账号做行级权限隔离和删除读回测试；未通过之前登录按钮不可上线。
- 预算以免费额度内的零额外费用为目标，不在未经用户同意时升级套餐。
