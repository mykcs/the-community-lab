# 韩文原文与信达雅中文翻译 · 题库发布标准

**约束：每道题及其可选答案必须先韩文、后简体中文；原文真实性、版权许可与翻译质量各自核验。** 本标准同时适用第一季、第二季，不因赶进度豁免。

## 翻译为什么是核心产品，而非装饰

用户的 [北极星愿望](../WISH.md) 不是制作另一套中文价值观题，而是：**读不懂韩文的人，在完整保留官方题目意思的前提下也能参加相同的测试，并得到与相同选择在官网完全相同的结果。** 浏览器自动翻译常丢失否定、条件、人物关系和语气，导致用户表面上“选了同一个按钮”，实际理解的题目已不同。因此翻译质量与评分等价必须**分别验收、同时过门**。

- **文本等价**：每一道韩文题、所有选项、量表词、必要提示及最终结果说明，都按「韩文完整可见 → 对应自然中文」展示；审校特别检查否定、时间、条件、强度、立场和反向题。争议及文化语境写独立译注，不在不知情的情况下改写题目。
- **答案身份不变**：翻译仅是展示层。题目用官方稳定 `sourceQuestionId`，选项用官方原始 `value` 存储和比较；即使中文措辞被修改、按钮排版变化或原站展示顺序更新，也不能改变答案值、轴归属、题目对应与评分方向。译审 UI 不得无意中把 O/X 或四／六级量表交换。
- **理解检验**：除双语逐字比对，再让不懂韩文的中文读者说明自己所理解的场景与选项方向；如发现忠于字面但实际会让中文读者作出不同选择，必须重审，不能以“机器翻译流畅”判 PASS。
- **结果语义等价**：官方数值、类别代码、方向和离散档须由 [评分验证矩阵](VERIFICATION-MATRIX.md) 核对；中文结果解释可写得自然，但必须不改变官网的判断范围与置信含义。不能以语言翻译为由调分，也不能用官方结果数字正确掩盖中文结果描述错误。

## 用户授权的临时「原题试填」与正式译文的区别（2026-10-30）

用户报告已取得**当前公开材料**的官方非营利翻译许可；项目未独立见到授权文件。基于完整任务目标，既有[译审草稿](https://mykcs.github.io/the-community-lab/translation-review/)中的两季 124 题、550 个选项已放入独立的[原题试填](https://mykcs.github.io/the-community-lab/questionnaire/)页面。真人韩中复核尚未完成。这个特例不改变下面的**正式译文审校门槛**：

- 只复用已发布草稿的相同源资源 SHA-256、题号及选项，依公开客户端已观察到的题序展示；不扩展授权用途或题目范围。
- 页面每一处关键入口明确写明「**非官方公开试填／中文 AI 初译、未真人复核／许可原件未独立核验**」。选项、题干均是可检查的草稿，不能称为正式中文译本。
- 浏览器可在本次会话内答题、回退、改选、导出敏感的本机答案。既不上传，也不调用原站提交／结果 API，不提供官方计分、嘉宾匹配或心理诊断。
- 自动测试能验证 87＋37 道、550 个选项、无重复的连续展示位置、版本与文本完整性；**不能替代**人工语义复核、权利核验、官方端到端路径与评分金标准。未来正式发布需独立完成这些审核，不允许因本次试填上线自动晋级。

## 「信、达、雅」如何验收

| 目标 | 具体要求 | 常见误差 |
| --- | --- | --- |
| 信 · 忠于原义 | 完整保留主体、行为、条件、否定、程度词、时间范围、双重否定以及价值判断对象 | 将「应当」译作「可以」；漏掉「只有／即使」；把「制度造成」改成「个人选择」 |
| 达 · 清楚易读 | 用当代自然简体中文，避免生硬韩语语序；熟悉中文的第一次阅读者能不借助外部解释选答 | 直译成拗口长句；含糊的「它」找不到指代 |
| 雅 · 准确而有分寸 | 语气得体，避免夸张、强加立场与讽刺；保留原题本身的尖锐程度 | 让有争议题目变得更激烈／更温和，改变作答倾向 |

「信」优先于「达」，「达」优先于「雅」；信达雅**不是**自由润色的理由。

## 一道题的数据合同

```json
{
  "id": "s2-001",
  "season": 2,
  "origin": "official_or_independent_demo",
  "source_text_ko": "원문은 여기 있습니다.",
  "translation_zh_cn": "这里展示对应的中文译文。",
  "options": [
    { "ko": "첫 번째 선택", "zh_cn": "第一个选项" }
  ],
  "source_url": null,
  "source_checked_at": null,
  "rights_status": "original_demo_or_pending_or_licensed",
  "translation_version": "demo-0.1.0",
  "review_status": "draft_or_bilingual_reviewed",
  "translator_note": null,
  "scoring_version": "independent-demo-0.1"
}
```

范例字符串用于说明字段，不代表真实节目题目。正式录入时 `origin` 与 `rights_status` 必须选择单一、真实的枚举值；节目原题需有明确来源证据、许可范围及可追溯版本。原题字段是准确引文而非 Agent 想象的韩文；遇到更新不得默默覆盖历史内容。

## 制作与审核流程

1. **核原文**：明确第几季、题号、原始页面、获取日期、版本和复制许可；法律上不可收录的原题留在研究索引中，不能复制进公开代码或截屏。
2. **初译**：一题一译，题干、量表、每一选项都翻译。记录术语对照，不擅自删改前提和否定。
3. **双语复核**：由另一位有能力核对韩中两种语言的人对照韩文原文，逐项检查语义和计分极性；必要时回译／盲评中文理解，复核不能用模型自评冒充独立人工复核。
4. **歧义标注**：文化语境或一词多义的情况以简短译注提示，不把说明文字偷偷放进原题文本；保留意见分歧与裁决理由。
5. **打版发布**：题库和译文分别有版本号，只有 `rights_status=licensed` 且 `review_status=bilingual_reviewed` 的节目原题可标为正式；本站原创演示题可在显眼标记下上线验证界面，不得与嘉宾原始结果相比较。
6. **回归检查**：自动验证每题均有韩中题干、选项数量对齐、题目 ID 唯一、题库与计分版本固定；用 iPhone 18 Pro Max 440×956 CSS px 查看长韩文和长中文是否截断。

### 私人答题记录的译文完整性

新下载的试填进度及完成记录除逐题 AI 草稿版本外，还记录当前所见中文题干、原始选项值和中文选项文字的构建期 SHA-256 指纹。恢复后若文字改了，即使编辑者忘记增加版本号，也必须重新阅读并确认对应选择；不会静默把旧答案说成已在新译文下作答。已生成的旧备份若没有此指纹，仍可导入，但只能按原有译文版本判断文字是否改变，无法补做历史证明。指纹只验证本站展示文本的变更，不证明中文翻译正确、官方计分一致、授权有效或 JSON 未被持有人修改；答案依然只留在本机，不自动上传。

### 两份独立审校草稿如何离线对照

公开 [译审草稿页](https://mykcs.github.io/the-community-lab/translation-review/) 支持每位审校者在**自己的设备／隔离浏览器资料**中修订中文、填写意见，再各自导出 JSON。协调者使用「对照两份审校 JSON」一次选择两份文件：浏览器先验证两份与当前韩文来源、来源指纹、权利记录及题序一致，再列出题干／选项译文冲突、修改意见、待复核项和两份同稿自报通过项；可下载**仅含题号和差异、不含审校备注或题目正文**的本地报告。整个过程不上传文件，不会合并覆盖原有草稿。

两份文件一致或都勾选通过，**不能证明**它们由两位独立且合格的韩中审校者完成，也不能自动将 `review_status` 升为 `bilingual_reviewed`。正式验收仍须单独核查审校人资格、独立性、日期、语义问题与裁决记录，并保护审校者隐私；此功能只是为真正的人工验收整理差异。

## 展示规则

- 第一行小标签：`한국어 원문` 或 `한국어 · 자체 제작 예시`，韩文题干保持完整可见。
- 第二行小标签：`中文翻译`，其下给出不减弱、不增强语气的简体中文译文。
- 每个答案选项按同一顺序展示韩文与中文；当原题有双重否定或文化背景时附可展开译注（不得影响答题）。
- 数据是本站原创演示时，首屏和结果页始终可见「非节目原题、非官方计分、不得用于嘉宾排名」。
- 不能仅凭看起来流畅就打勾「人工已复核」；尚未完成时如实标 `draft`。
